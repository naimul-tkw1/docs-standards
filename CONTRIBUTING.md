# Contributing

Thanks for helping improve these standards.

## How to propose a change

1. Open an issue describing the problem or the new standard you'd like to see.
2. Fork the repo and create a branch (`feature/<short-name>` or `fix/<short-name>`).
3. Make your change and open a pull request that links the issue.

## Writing a standard

- One standard per file in `standards/`, named in kebab-case (for example `naming-conventions.md`).
- Start each file with a short header block:

  ```markdown
  # <Standard name>

  **Status:** Draft | Active | Deprecated
  **Version:** 1.0
  **Last updated:** YYYY-MM-DD
  ```

- Use clear headings, keep sentences short, and include examples.
- Use "must", "should" and "may" deliberately to signal required, recommended and optional rules.
